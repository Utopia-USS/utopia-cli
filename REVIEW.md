## 2. What was dropped or compromised, and why

### `.utopia.yaml` reader is wired but not consumed
`UtopiaConfig.load()` exists and parses correctly, but the
`CreateSubCommand` hierarchy does not yet thread its values into the
arg defaults. Doing it cleanly requires re-reading config before
`argParser.addOption(defaultsTo: ...)` runs, which means restructuring
the constructor order. Deferred to a follow-up to keep this PR
reviewable.

### Stale docs files not deleted
`SETUP.md`, `PUBLISHING.md`, `UPDATE_TEMPLATE.md`, and the `scripts/`
directory were planned for deletion (consolidated into
`CONTRIBUTING.md`). The auto-mode classifier blocked the recursive
`rm`. Their content is superseded but the files remain in the tree —
maintainer should delete them in a follow-up commit:

```bash
git rm SETUP.md PUBLISHING.md UPDATE_TEMPLATE.md
git rm -r scripts/
```

### Brick template lint warnings
The generated project still emits `directives_ordering` info-level
lints in pre-existing template files (`app/`, `common/`, `util/`).
These were present in the previous brick and were not in scope for
this rebuild. The new counter files are clean.

### `app_localizations.g.dart` errors at first `flutter analyze`
The localization generator file is not committed — by design, it's
generated by `build_runner`. A first-time user gets two analyzer
errors until they run `dart run build_runner build`. Documented in
`DEVELOPMENT.md` and the post-create "Next steps" output.

### MCP `tools/list` empty in stdin-pipe smoke test
The `utopia mcp` server handles the `initialize` handshake correctly,
advertises the `tools` capability, and fires three
`notifications/tools/list_changed` (proving `registerTool` ran). But a
direct `tools/list` over piped stdin returns `{"tools": []}`. Code path
matches reference implementations; the empty result may be a quirk of
the one-shot pipe lifecycle in the test harness. Needs verification
against a live MCP client (Claude Code, Cursor) before declaring the
command production-ready. Marked experimental in the README.

### Schema for `.claude/settings.json` is unverified
The generated `marketplaces`/`enabledPlugins` keys match the public
schema URL in the file header, but the live Claude Code consumer
schema for marketplaces may differ in field names. If users hit
"unrecognized field" warnings, fall back to documenting
`/plugin marketplace add Utopia-USS/utopia-flutter-skills` in
`.claude/README.md` (already present as a backup instruction).

## 3. Open issues / known limitations

1. **Pub-cache resolution untested in CI.** The `BrickLocator`'s
   hosted/global-package paths are exercised only through unit tests
   that fake the layout. Real verification requires
   `dart pub global activate utopia_cli` end-to-end.
2. **`flutter create` is required at runtime.** The CLI shells out to
   `flutter create` to fill in `android/`, `ios/`, etc. If
   `flutter` is not on PATH, generation fails with a clear error —
   but there's no pre-flight check (could be added later).
3. **`.claude/` only generated when `--skills` is true.** Because we
   use `{{#skills_enabled}}.claude{{/skills_enabled}}` as a path
   prefix, Mason resolves to a `.claude/` directory only when the
   variable is truthy. If a user later opts in, they have to
   `claude /plugin marketplace add` manually or regenerate the
   project — there's no `utopia init skills` command yet.
4. **Deprecation timeline for `utopia_arch_cli`.** Plan says removal
   in 0.3.0. If the package has any downstream users we're not aware
   of, extending the runway one minor is cheap.
5. **License (BSD-2-Clause) applied here only.** The skills repo
   (`utopia-flutter-skills` / local `utopia_claude_skills`) is also
   intended to receive the same license under this task. Done as a
   separate commit in the skills repo — see manual step #5 below.

## 5. Suggested next steps (P2 backlog)

1. **`utopia add screen <name>`** — wrap the existing `utopia-mason`
   `screen` brick into a CLI subcommand. Trivial since the brick is
   already published.
2. **`utopia add state <name>`** — generate a `useXState()` hook +
   `_providers.dart` entry. Pairs with the migration skill.
3. **`utopia migrate bloc`** — thin wrapper that registers the
   marketplace if missing and prints
   `claude /utopia-hooks-migrate-bloc:migrate` as the next command.
4. **Plumb `.utopia.yaml` defaults into the argParser.** Read config in
   the runner, pass into each `CreateSubCommand` constructor.
5. **`utopia init skills`** — for projects created with `--no-skills`
   that later want to opt in.
6. **CI pipeline** — at minimum `dart analyze` + `dart test` +
   `dart pub publish --dry-run` on PR. Optional: a smoke job that
   activates the CLI and runs `create flutter_app` in a temp dir.
7. **Welcome opt-in for first-time users** — first run could prompt
   for default org and write `.utopia.yaml` to `$XDG_CONFIG_HOME` (no
   files written to bare `$HOME`).
